wenet

WeNet 是生产级的端到端语音识别工具包，支持流式与非流式识别；昇腾侧通过 torch-npu 把计算调度到 NPU。

本文以 aishell-1 数据集为例，按 WeNet 官方 NPU 实验脚本 （官方教程），在单卡昇腾 NPU 上跑通 数据下载 → 数据准备 → 训练 → 推理 → 导出 全流程。

阅读本文前，请先按 快速安装昇腾环境 准备好 CANN 与驱动。

Note

本文与看护流水线跟踪上游 main 分支：WeNet 最新的正式 release（v3.1.0，2024-05 发布）不含 NPU 训练/推理脚本 examples/aishell/s0/run_npu.sh，只有 main 分支提供该脚本。因此看护流水线用 fixed_ref: main 跟踪 main 的 HEAD 提交，本文中的 <ref> 取 main。

1. 加载 CANN 环境

新开终端后 CANN 变量不会自动生效。npu-smi 常见位于 /usr/local/sbin，需要把该目录加入 PATH。

source /usr/local/Ascend/ascend-toolkit/set_env.sh
export PATH=/usr/local/sbin:$PATH
test -n "$ASCEND_HOME_PATH"
command -v npu-smi

ASCEND_HOME_PATH 应非空，npu-smi 应能找到。

2. 检查环境是否就绪

检查 Python 版本：

python --version

输出结果如下：

Python 3.10.xxx

检查 torch / torch-npu 是否装好且 NPU 设备可用（下面的命令用 Python 执行）：

import torch
import torch_npu

print('torch:', torch.__version__)
print('torch_npu:', torch_npu.__version__)
print('npu available:', torch.npu.is_available())
print('npu count:', torch.npu.device_count())

输出结果如下：

torch: xxx
torch_npu: xxx
npu available: True
npu count: 1

Note

如果 import torch_npu 失败，回到 Ascend PyTorch 安装文档 检查 torch / torch-npu / CANN 三方兼容矩阵。

3. 获取 WeNet 源码

将 <ref> 替换为 main（main 分支才有 NPU 脚本 examples/aishell/s0/run_npu.sh）：

git clone https://github.com/wenet-e2e/wenet.git
cd wenet
git checkout <ref>
test -f examples/aishell/s0/run_npu.sh && echo "run_npu.sh ok"

main 分支上 examples/aishell/s0/run_npu.sh 存在。

4. 安装 WeNet 与依赖

安装 WeNet 及其 NPU 依赖。[torch-npu] extra 已将 torch / torch-npu / torchaudio 钉在推荐版本 2.2.0，并附带 numpy<2；requirements.txt 只约束 deepspeed>=0.14.0，为避免 pip 解析到与 torch 2.2.0 不兼容的 0.16+，安装后显式回钉 0.14.4。

source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd wenet
pip install -e .[torch-npu]
pip install -r requirements.txt
pip install "deepspeed==0.14.4"
# train_utils.py 无条件 import tensorboardX；requirements.txt 是开发全量清单
# （含 flake8/clang-format/openai-whisper 等与训练无关项），aarch64 上任一包
# 解析失败会导致整张清单未安装，且失败被命令块尾部的 rc 静默吞掉，
# 故训练核心依赖在安装步骤显式补齐（装失败将在此步骤快速失败）
pip install tensorboardX

安装 sox（sox 命令与 libsox-dev 头文件）：

pip install sox
apt-get update && apt-get install -y sox libsox-dev || true

5. 下载数据（stage -1）

从 Hugging Face 下载 aishell-1 数据集（约 15.6 GB），然后创建软链接适配 WeNet 脚本期望的目录结构。

数据集源 JazerJu/aishell1-full-slr33 是 OpenSLR 33 两个原始压缩包的字节保真 镜像：data_aishell.tgz / resource_aishell.tgz 的字节数（15582913665 / 1246920）与 openslr.org 上的原档 一致，解压后的目录结构因此与官方 local/download_and_untar.sh 完全对齐。也可以直接用 OpenSLR 原站替换下面 的下载命令。

如果访问 Hugging Face 较慢，可先切换到国内镜像（该设置只影响当前终端）：

export HF_ENDPOINT=https://hf-mirror.com

# hf_transfer 让这个 15.6 GB 的单文件走分片并行下载，是相对单连接拉取的主要提速点；
# 装不上时下面的 snapshot_download 仍会走普通 HTTP 路径
pip install -q "huggingface_hub[hf_transfer]" || pip install -q huggingface_hub
if python -c "import hf_transfer" >/dev/null 2>&1; then
  export HF_HUB_ENABLE_HF_TRANSFER=1
fi
mkdir -p /root/asr-data/OpenSLR/33
# 用 local_dir 固定下载落点：落点与下面解压出的数据都在 /root/.cache 上（runner 的共享缓存盘），
# 跨 run 复用；已经完整的文件由 snapshot_download 按 etag / 字节数跳过，中断的 tgz 续传
python -c "
from huggingface_hub import snapshot_download
snapshot_download(
    'JazerJu/aishell1-full-slr33',
    repo_type='dataset',
    local_dir='/root/.cache/huggingface/datasets/aishell1-slr33',
    max_workers=8,
)
"
echo "=== 下载后目录结构 ==="
ls -l /root/.cache/huggingface/datasets/aishell1-slr33
# 解压数据集：data_aishell.tgz 内层 wav/ 下是按说话人二次打包的 *.tar.gz，
# 必须再解压内层包（对齐官方 local/download_and_untar.sh），否则 stage 0 找不到任何 wav。
# 解压产物随 /root/.cache 上的共享缓存盘跨 run 保留：用标记文件 wav/.extracted 做幂等判断，
# 首次解压后（约 40min）后续 run 直接跳过整段；缓存盘被清空时标记随之消失，自动重新解压
cd /root/.cache/huggingface/datasets/aishell1-slr33
if [ ! -f data_aishell/wav/.extracted ]; then
  tar xzf data_aishell.tgz
  tar xzf resource_aishell.tgz
  (
    cd data_aishell/wav
    for x in *.tar.gz; do tar xzf "$x"; done
    rm -f *.tar.gz
    touch .extracted
  )
fi
# 创建软链接
ln -sf /root/.cache/huggingface/datasets/aishell1-slr33/data_aishell /root/asr-data/OpenSLR/33/data_aishell
ln -sf /root/.cache/huggingface/datasets/aishell1-slr33/resource_aishell /root/asr-data/OpenSLR/33/resource_aishell
touch /root/asr-data/OpenSLR/33/data_aishell/.complete
touch /root/asr-data/OpenSLR/33/resource_aishell/.complete
echo "=== 软链接验证 ==="
ls -la /root/asr-data/OpenSLR/33/

验证 data_aishell 与 resource_aishell 两个数据包均已就绪：

echo "=== 检查下载标记文件 ==="
ls /root/asr-data/OpenSLR/33/data_aishell/.complete /root/asr-data/OpenSLR/33/resource_aishell/.complete
echo "=== 检查数据目录 ==="
ls /root/asr-data/OpenSLR/33/data_aishell/ | head -2
ls /root/asr-data/OpenSLR/33/resource_aishell/ | head -2

输出结果如下：

=== 检查下载标记文件 ===
/root/asr-data/OpenSLR/33/data_aishell/.complete
/root/asr-data/OpenSLR/33/resource_aishell/.complete
=== 检查数据目录 ===
transcript

7. 生成 CMVN、词典与 data.list（stage 1-3）

stage 1 去除转写文本中的词间空格（普通话字符建模标准做法）并计算全局 CMVN 统计，stage 2 从训练转写生成 字符级词典 data/dict/lang_char.txt，stage 3 把 wav.scp / text 组织为训练可读的 data.list （raw 格式，每行一条 utterance 的 JSON）。三者均为训练（stage 4）的前置产物，缺少时训练启动即报 FileNotFoundError: data/dict/lang_char.txt：

cd wenet/examples/aishell/s0
bash run_npu.sh --stage 1 --stop_stage 3 --data /root/asr-data/OpenSLR/33

验证三个前置产物（data.list 行数与对应 wav.scp / text 一致）：

cd wenet/examples/aishell/s0
test -f data/train/global_cmvn && echo "global_cmvn ok"
test -f data/dict/lang_char.txt && echo "lang_char.txt ok"
wc -l data/train/data.list data/dev/data.list data/test/data.list | awk '{print $1, $2}'

输出结果如下：

global_cmvn ok
lang_char.txt ok
120098 data/train/data.list
14326 data/dev/data.list
7176 data/test/data.list
141600 total

8. 模型训练（stage 4）

run_npu.sh 中实现了 NPU 卡号的自动获取与相关环境变量设置，可直接启动昇腾 NPU 上的模型训练。为控制时长， 将 max_epoch 从 240 缩短到 1（其余参数全部保持脚本默认值）：

source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd wenet/examples/aishell/s0
cp conf/train_conformer.yaml conf/train_conformer_1ep.yaml
sed -i 's/max_epoch: .*/max_epoch: 1/' conf/train_conformer_1ep.yaml
# NPU fork-safety 适配：主进程初始化 CANN 后 fork 出的 DataLoader worker 会段
# 错误（torch_npu 2.2 + CANN 8.0 已知问题），必须单进程读取（num_workers=0）。
# torch 2.2 还要求 num_workers=0 时 persistent_workers=False 且
# prefetch_factor=None，否则 DataLoader 构造直接 ValueError，一并条件化
sed -i 's/^num_workers=.*/num_workers=0/' run_npu.sh
sed -i 's/persistent_workers=True/persistent_workers=args.num_workers > 0/g' "$(git rev-parse --show-toplevel)/wenet/utils/train_utils.py"
sed -i 's/prefetch_factor=args.prefetch/prefetch_factor=args.prefetch if args.num_workers > 0 else None/g' "$(git rev-parse --show-toplevel)/wenet/utils/train_utils.py"
# 源码改写校验：sed 路径或匹配失败时立即报错，避免被命令块尾部的 rc=0 吞掉
grep -q "persistent_workers=args.num_workers > 0" "$(git rev-parse --show-toplevel)/wenet/utils/train_utils.py"
grep -q "if args.num_workers > 0 else None" "$(git rev-parse --show-toplevel)/wenet/utils/train_utils.py"
bash run_npu.sh --stage 4 --stop_stage 4 --train_config conf/train_conformer_1ep.yaml --data /root/asr-data/OpenSLR/33

训练完成后检查输出：

cd wenet/examples/aishell/s0
ls -la exp/conformer/train.yaml
ls exp/conformer/epoch_*.pt

输出结果如下：

... exp/conformer/train.yaml
exp/conformer/epoch_0.pt

9. 测试推理（stage 5）

stage 5 为模型测试推理阶段，把测试集中的语音文件识别为文本。此外，当 ${average_checkpoint} 为 true （脚本默认值）时，本阶段会把交叉验证集上最佳的 ${average_num} 个模型平均，生成增强模型 avg_1.pt，供解码 与导出使用：

# CANN 环境必须显式加载：否则 LD_LIBRARY_PATH 缺少 libascendcl 等库路径，
# recognize.py 里 import torch_npu 会静默失败（ImportError 被
# is_torch_npu_available 吞掉只打印提示），随后 torch.device('npu') 直接崩溃
source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd wenet/examples/aishell/s0
bash run_npu.sh --stage 5 --stop_stage 5 --average_num 1 --data /root/asr-data/OpenSLR/33

验证推理结果（测试集 7176 条全部识别完成，并抽样打印前两条识别文本）：

cd wenet/examples/aishell/s0
test -f exp/conformer/avg_1.pt && echo "avg_1.pt ok"
wc -l exp/conformer/ctc_greedy_search/text | awk '{print $1}'
head -2 exp/conformer/ctc_greedy_search/text

输出结果如下（识别文本随模型收敛情况变化）：

avg_1.pt ok
7176
xxx
xxx

10. 导出训练好的模型（stage 6）

stage 6 为模型导出阶段，wenet/bin/export_jit.py 使用 Libtorch 导出以上训练好的模型（基于 stage 5 生成的 avg_1.pt），导出的模型可用于其他编程语言（如 C++）的推理：

source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd wenet/examples/aishell/s0
bash run_npu.sh --stage 6 --stop_stage 6 --average_num 1

验证导出产物：

cd wenet/examples/aishell/s0
test -f exp/conformer/final.zip && echo "final.zip ok"
test -f exp/conformer/final_quant.zip && echo "final_quant.zip ok"

输出结果如下：

final.zip ok
final_quant.zip ok
