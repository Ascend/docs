MiniOneRec

MiniOneRec 是全开源的生成式推荐框架：把每件商品编码成 3 层语义 ID（SID），再用 LLM 按「下一个 SID」的方式生成推荐结果。本文在单张昇腾 NPU 上完成 SID 监督微调（SFT）、约束解码评估与推荐导向 RL 三个阶段。

前两个阶段不改上游源码：sft.py 的设备由 transformers 自己选到 npu:0，evaluate.py 则把设备判定写在模块级，靠一条只在评估与 RL 命令上生效的 PYTHONPATH 注入 transfer_to_npu。RL 阶段有三处写死值与单卡运行冲突，用一条 sed 就地替换。

阅读本文前，请先按 快速安装昇腾环境 准备好 CANN 与驱动。

1. 加载 CANN 环境

新开终端后 CANN 变量不会自动生效。

export PATH=/usr/local/sbin:/usr/local/bin:$PATH
source /usr/local/Ascend/ascend-toolkit/set_env.sh

2. 检查环境是否就绪

source /usr/local/Ascend/ascend-toolkit/set_env.sh
test -n "$ASCEND_HOME_PATH"
command -v npu-smi
npu-smi info
python --version

npu-smi 打印出设备列表、Health 为 OK 即可；若提示找不到 npu-smi，回到 快速安装昇腾环境 检查驱动与设备挂载。

3. 获取代码

将 <ref> 替换为上游最新的 main 提交。

echo "${UPSTREAM_REF}"

git clone --depth 1 https://github.com/AkaliKong/MiniOneRec.git
cd MiniOneRec
git checkout <ref>

4. 安装依赖

上游 requirements.txt 面向 CUDA 环境（torchrec、fbgemm_gpu 是 +cu118 安装包，另带整套 nvidia-*-cu12 运行库），NPU 上改用与 CANN 9.1.0 配套的 torch 栈单独安装。

source /usr/local/Ascend/ascend-toolkit/set_env.sh
pip install torch==2.9.0 torch-npu==2.9.0.post2
pip install transformers==4.57.1 accelerate==1.10.1 datasets==4.2.0 \
    tokenizers==0.22.1 fire==0.7.1 pandas==2.2.2 tqdm bitsandbytes==0.48.1 \
    trl==0.24.0 scikit-learn==1.5.2 wandb==0.22.2

bitsandbytes 钉在 aarch64 有预编译包的 0.48.1：sft.py 与 evaluate.py 顶部的 import bitsandbytes as bnb 从未被实际使用，但不改源码就绕不开这行 import，必须让它能导入。trl 提供 rl.py 用的 GRPOConfig，scikit-learn 提供 ndcg_score，wandb 则是 sasrec.py 无条件导入的。sft.py 的 TrainingArguments 默认 report_to="all"，装好 wandb 后会尝试 wandb.init() 并因缺少 API key 失败，所以第 8 节导出 WANDB_MODE=disabled。

5. 观察默认行为：两个入口的设备走向不一样

只 import torch_npu 不会改写 torch.cuda 这一面，而 MiniOneRec 的两个入口对它的依赖并不相同。sft.py 把设备选择交给 TrainingArguments，transformers 的设备链里 NPU 分支排在 CUDA 之前，所以能直接拿到 npu:0；evaluate.py 在模块级就把 device 固化成 "cpu"。下面这段命令能同时看到两种结果：

source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd MiniOneRec
python -c "
import torch, torch_npu
from transformers import TrainingArguments
print('npu available:', torch.npu.is_available())
print('cuda mapped:', torch.cuda.is_available())
print('evaluate.py device:', 'cuda' if torch.cuda.is_available() else 'cpu')
print('trainer device:', TrainingArguments(output_dir='/tmp/probe-default').device)
"

输出结果如下：

npu available: True
cuda mapped: False
evaluate.py device: cpu
trainer device: npu:0

6. 为评估与 RL 启用 NPU 映射

torch_npu.contrib.transfer_to_npu 把 torch.cuda 这一整套接口映射到 NPU，导入即生效。为了让映射只作用于需要它的命令，把 sitecustomize.py 放进独立目录、通过 PYTHONPATH 挂到命令上——不写进 site-packages，其他进程不受影响。

mkdir -p /tmp/minionerec-npu-shim
cat > /tmp/minionerec-npu-shim/sitecustomize.py <<'INS'
import torch_npu.contrib.transfer_to_npu  # noqa: F401
INS

确认映射只覆盖挂了 PYTHONPATH 的那条命令：

source /usr/local/Ascend/ascend-toolkit/set_env.sh
cd MiniOneRec
python -c "import torch; print('default process:', 'cuda' if torch.cuda.is_available() else 'cpu')"
PYTHONPATH=/tmp/minionerec-npu-shim python -c "
import torch
print('with shim:', 'cuda' if torch.cuda.is_available() else 'cpu')
print('tensor landed on:', torch.zeros(1, device='cuda').device.type)
"

输出结果如下（代码里写的是 cuda，张量实际落在 NPU）：

default process: cpu
with shim: cuda
tensor landed on: npu

确认仓库源码没被动过（前面的检查与注入都不落在仓库里）：

cd MiniOneRec
test -z "$(git status --porcelain)" && echo "source untouched"

输出结果如下：

source untouched

7. 下载基座模型与预处理数据

基座模型取 Qwen2.5 的 base 版，Instruct 版会让约束解码失效。模型与预处理数据都在 HuggingFace 上：Qwen/Qwen2.5-0.5B 是权重，kkknight/MiniOneRec 是官方预处理好的 Amazon Industrial_and_Scientific 数据。数据侧只取 SID 索引、训练 / 验证 / 测试 CSV 与 info/ 下的 SID-条目清单；.npy 嵌入文件只有 RQ/SID 构建阶段需要，跳过。

cd MiniOneRec
python -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='Qwen/Qwen2.5-0.5B', local_dir='./Qwen2.5-0.5B')"
python -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='kkknight/MiniOneRec', allow_patterns=['Amazon/index/Industrial_and_Scientific.index.json','Amazon/index/Industrial_and_Scientific.item.json','Amazon/train/Industrial_and_Scientific_5_2016-10-2018-11.csv','Amazon/valid/Industrial_and_Scientific_5_2016-10-2018-11.csv','Amazon/test/Industrial_and_Scientific_5_2016-10-2018-11.csv','Amazon/info/Industrial_and_Scientific_5_2016-10-2018-11.txt'], local_dir='data')"

8. SFT 训练

单卡跑 1 epoch：sample=600 限制每个子数据集（SID 序列 / SID-条目对齐 / 融合序列推荐）各取 600 条，cutoff_len=256 截断序列。完整训练（8 卡 A100、全量数据）见上游 sft.sh。

source /usr/local/Ascend/ascend-toolkit/set_env.sh
export ASCEND_RT_VISIBLE_DEVICES=0
export WANDB_MODE=disabled
cd MiniOneRec
python sft.py \
    --base_model ./Qwen2.5-0.5B \
    --train_file ./data/Amazon/train/Industrial_and_Scientific_5_2016-10-2018-11.csv \
    --eval_file ./data/Amazon/valid/Industrial_and_Scientific_5_2016-10-2018-11.csv \
    --output_dir ./sft_out \
    --batch_size 8 \
    --micro_batch_size 2 \
    --num_epochs 1 \
    --cutoff_len 256 \
    --sample 600 \
    --category Industrial_and_Scientific \
    --sid_index_path ./data/Amazon/index/Industrial_and_Scientific.index.json \
    --item_meta_path ./data/Amazon/index/Industrial_and_Scientific.item.json \
    --freeze_LLM False \
    --train_from_scratch False

训练完成后校验产物（model.safetensors + config.json + tokenizer 配置）：

cd MiniOneRec
test -f sft_out/final_checkpoint/model.safetensors && echo "model saved"
test -f sft_out/final_checkpoint/config.json && echo "config saved"
test -f sft_out/final_checkpoint/tokenizer_config.json && echo "tokenizer saved"
grep -o '"model_type": "[a-z0-9_.-]*"' sft_out/final_checkpoint/config.json

输出结果如下：

model saved
config saved
tokenizer saved
"model_type": "qwen2"

9. 约束解码评估

用上一节得到的 final_checkpoint 在 test 切片上做 beam search 评估，再算 HR/NDCG/CC。CC（无效 SID 生成数）必须为 0——ConstrainedLogitsProcessor 用 trie 约束每步只允许合法 SID 前缀 token，这是约束解码在 NPU 上生效的关键信号。本节用 num_beams=20、batch_size=2。

切出 test 子集：

cd MiniOneRec
head -n 200 data/Amazon/test/Industrial_and_Scientific_5_2016-10-2018-11.csv > test_small.csv
wc -l test_small.csv

运行评估（进度条与 transformers 警告走 stderr，stdout 只有 category 名）：

source /usr/local/Ascend/ascend-toolkit/set_env.sh
export ASCEND_RT_VISIBLE_DEVICES=0
cd MiniOneRec
PYTHONPATH=/tmp/minionerec-npu-shim python evaluate.py \
    --base_model ./sft_out/final_checkpoint \
    --info_file ./data/Amazon/info/Industrial_and_Scientific_5_2016-10-2018-11.txt \
    --test_data_path test_small.csv \
    --result_json_data ./eval_result.json \
    --category Industrial_and_Scientific \
    --num_beams 20 --batch_size 2

输出结果如下（进度条走 stderr）：

industrial and scientific items
...

校验预测产物：

cd MiniOneRec
python -c "import json; d=json.load(open('eval_result.json')); print(len(d)); print('predict' in d[0])"

输出结果如下：

计算 HR/NDCG/CC。HR/NDCG 随训练状态浮动，判断约束解码是否生效看 CC 是否为 0：

cd MiniOneRec

10. 推荐导向 RL

RL 在 SFT 产物上再做一轮 GRPO：每个 prompt 采样多条候选、组内归一化奖励、并用 KL 约束贴近参考模型；动作空间是有限的 SID 列表，候选由约束 beam search 生成。

上游有三处写死值与单卡运行冲突，用一条 sed 就地替换（都是单行，只在本次运行生效）：

  • optim="paged_adamw_32bit" 走 bitsandbytes，而 bitsandbytes 只提供 CPU、CUDA 等后端，没有 NPU 实现，换成 torch 原生 adamw_torch。

  • sample = -1 决定 SID 数据集与「标题→SID」数据集的样本数，-1 会把整个商品目录展开，训练会拉长到上万步，改为 40。

  • RLSeqTitle2SidDataset(..., sample=10000) 是第三个数据集，采样上限写死在调用处，不受上面那个变量影响；训练集切到 40 行后样本池只有 40，sample(10000) 会抛 Cannot take a larger sample than population，同样改为 40。

本节会就地修改 rl.py 三行。

cd MiniOneRec
sed -i -e 's/optim="paged_adamw_32bit"/optim="adamw_torch"/' \
       -e 's/^    sample = -1$/    sample = 40/' \
       -e 's/sample=10000/sample=40/' rl.py
grep -c 'optim="adamw_torch"' rl.py
grep -c '^    sample = 40$' rl.py
grep -c 'sample=40' rl.py

输出结果如下：

1
1
1

三个数据集都按 40 取样，所以把训练集也切到 40 行（pandas 允许取样数等于总体数）：

cd MiniOneRec
python - <<'PY'
import pandas as pd

df = pd.read_csv('data/Amazon/train/Industrial_and_Scientific_5_2016-10-2018-11.csv')
df.head(40).to_csv('data/rl_train_40.csv', index=False)
print('rl train rows:', len(pd.read_csv('data/rl_train_40.csv')))
PY

输出结果如下：

rl train rows: 40

在 0 号卡上跑 1 epoch。train_batch_size 必须能被 num_generations 整除；num_generations 同时是 beam 宽度，本节取 2。

source /usr/local/Ascend/ascend-toolkit/set_env.sh
export ASCEND_RT_VISIBLE_DEVICES=0
cd MiniOneRec
PYTHONPATH=/tmp/minionerec-npu-shim python rl.py \
    --model_path ./sft_out/final_checkpoint \
    --train_file ./data/rl_train_40.csv \
    --eval_file ./data/Amazon/valid/Industrial_and_Scientific_5_2016-10-2018-11.csv \
    --info_file ./data/Amazon/info/Industrial_and_Scientific_5_2016-10-2018-11.txt \
    --category Industrial_and_Scientific \
    --train_batch_size 4 \
    --eval_batch_size 4 \
    --num_generations 2 \
    --num_train_epochs 1 \
    --gradient_accumulation_steps 1 \
    --learning_rate 1e-5 \
    --beta 1e-3 \
    --beam_search True \
    --reward_type ranking \
    --sync_ref_model True \
    --test_during_training False \
    --eval_step 1.0 \
    --output_dir ./rl_out \
    --sid_index_path ./data/Amazon/index/Industrial_and_Scientific.index.json \
    --item_meta_path ./data/Amazon/index/Industrial_and_Scientific.item.json

输出结果如下（数据集对象与进度条走 stderr）：

Industrial_and_Scientific
...

日志里的 reward、reward_std、loss、grad_norm、kl 会一直是 0，这不是故障。rule_reward 要求生成的 SID 与目标完全相等；上一节只训 1 epoch，精确命中率接近 0，组内两条候选都命不中，ndcg_rule_reward 还会把整组补 0，GRPO 的组内优势因此无从计算，梯度自然为 0。到这里三个阶段都已跑通；要看到非零的训练信号，需要更充分的 SFT。

校验 rl.py 结尾的两步落盘（trainer.save_model 与 model.save_pretrained）：

cd MiniOneRec
test -f rl_out/final_checkpoint/model.safetensors && echo "rl model saved"
test -f rl_out/final_checkpoint/config.json && echo "rl config saved"
test -f rl_out/final_checkpoint/tokenizer_config.json && echo "rl tokenizer saved"

输出结果如下：

rl model saved
rl config saved
rl tokenizer saved
